# `MODEL_PROVIDER=glm` wired into `createModel`, scoped to the CLI seam only — the deployed stack stays Bedrock-only

The README had to document `MODEL_PROVIDER=glm` as an opt-in alternative alongside the zero-credential Bedrock default. `create-model.ts`'s own doc comment (written with the Agent API) said this was deliberately not wired in: "add it alongside a ticket that actually runs against it ... rather than shipping an untested branch." That never happened — `MODEL_PROVIDER` was read nowhere in `src/` before this change, confirmed by grep. Documenting an env var the code silently ignores is worse than either alternative: `MODEL_PROVIDER=glm` in the README would produce Bedrock anyway, with no error, in the one artifact a reviewer reads cold — a claim the repo doesn't back up, not a decision anyone made on purpose.

`createModel` (`src/model/create-model.ts`) now branches on `MODEL_PROVIDER` the same one-factory shape the gateway factory then used for its fixture/live mode switch (since removed, `ADR-0005`): one factory function, `MODEL_PROVIDER=glm` selects `OpenAIModel` (`@strands-agents/sdk/models/openai`, `api: 'chat'`) pointed at z.ai's OpenAI-compatible endpoint, everything else falls through to the existing Bedrock branch unchanged. Env var names come from the project spec's own config table (`MODEL_ID`, `MODEL_API_KEY`, `MODEL_BASE_URL`) — not `spike/`'s `GLM_API_KEY`, which is superseded raw material (the spec's own notes already say so for `SCRATCH.md`; the same applies to anything spike-only that never made it into the spec). Missing `MODEL_API_KEY` under `MODEL_PROVIDER=glm` throws a clear, immediate error rather than falling back to Bedrock silently or failing later inside the OpenAI client with a less legible message — mirroring the gateway factory's own throw-on-missing-credential behavior at the time.

This is intentionally the smallest change that makes the README claim true, not a second GLM feature ticket: no change to `structuredOutputSchema` handling, no new test coverage of GLM's actual chat behavior against z.ai (the spike already proved that shape works), no wiring into `infra/support-investigator-stack.ts`. The deployed Lambdas set no `MODEL_API_KEY` and have no egress story for `api.z.ai` — `MODEL_PROVIDER=glm` is reachable only through `pnpm dev`'s CLI commands, on a developer's own machine, exactly the "free local iteration" role `ADR-0003` already assigned it. If GLM ever needs to run inside the deployed stack, that's a real, separate architectural decision (an SSM parameter, an IAM/network story for outbound HTTPS to z.ai) — not something this ticket's own scope (a demo script and README) should make by touching the CDK stack.
