# Cut over to the resource-oriented Investigation, remove Strands and the golden-ticket harness

The original prototype and the resource-oriented Investigation had coexisted since the latter was introduced: `POST /investigate` (Strands `Agent` → `McpClient` → this app's own Support MCP endpoint → free-text `InvestigationResult`, gated by a global confidence score) sat alongside `POST /investigations` (deterministic Fulfillment Playbook → typed Evidence Ledger → pure Finding Policy → canonical Finding Code and Investigation Decision). This cutover ends that coexistence with no compatibility layer: the resource-oriented Investigation is now the only first-party investigation workflow the API, CLI and web app expose.

**Removed, with no replacement.** `src/api/app.ts` (`POST /investigate`, the `{ proposed, final }` envelope), `src/api/lambda-handler.ts` (its Lambda wrapper), `src/agent/` (the Strands `Agent` loop, tool-activity observation, the structured-output tool name), `src/domain/policy-gate.ts` and its sabotage battery (the old global-confidence gate ADR-0037/0038 already replaced conceptually; this cutover deletes the code), `src/domain/investigation-result.ts` (`ProposedFinal`), `src/model/create-model.ts` (the Strands `BedrockModel`/`OpenAIModel` factory, and with it `MODEL_PROVIDER=glm` — ADR-0018 is superseded, ADR-0003 amended), and `@strands-agents/sdk` itself from `package.json` (ADR-0042's deferred removal is now resolved). `infra/support-investigator-stack.ts` drops the Agent API Lambda, its `bedrock:InvokeModel` policy, the `/investigate` route, and the `AgentDemoKeyPolicy` grant that existed only so that Lambda's own outbound `McpClient` calls could carry `x-demo-key` (ADR-0019 amended) — "no longer reads a demo key for that internal hop" is now literally true because the internal hop is gone, not merely unused.

**Kept, unchanged.** `/mcp` and its demo-key gating (ADR-0019's core decision stands: a real, external adapter per ADR-0039, not an internal hop), `src/security/read-demo-key.ts` (now called only by the authorizer), and `src/api/intake-injection-sabotage-battery.ts` — new-contract code testing `investigations-app.ts`'s `buildIntake`, unrelated to the deleted `policy-gate-sabotage-battery.ts` despite the similar name and shape.

**CLI, simplified beyond just deleting the `investigate` command.** `order-context`/`simulate-fulfillment`/`search-knowledge` used to take already-structured CLI arguments, wrap them into a natural-language sentence, hand that to a Strands `Agent`, and let the model parse the arguments back out to call one Support MCP tool — pure overhead once Strands is gone. They then called the official MCP SDK `Client` directly with structured arguments, keeping the CLI's live proof that Support MCP works as an external adapter (matching NOTES.md's own use of these commands as a fixture smoke check) without a model or a natural-language round trip anywhere in the path. A later change migrated both the Support MCP server and client usage to the split MCP SDK v2 packages; Strands' `McpClient` was only ever a transport proof here, never a product dependency.

**The eval/insights pipeline was retired, not repointed.** `src/evals/golden-tickets.ts`'s 15 tickets were 14 payment/cancellation/generic-order/unrelated-out-of-stock/permission cases and exactly one real `STOCK_WITHOUT_DELIVERY_OPTIONS` scenario — precisely what this cutover's acceptance criteria say must stop being active focused acceptance scenarios. `run-eval-suite.ts`, `fake-model.ts`, `eval-report.ts`, `sabotage-check.ts` and `pnpm evals`/`pnpm evals:live` all existed to drive and gate that 15-ticket harness through the now-deleted Strands loop; none of it has a new-contract equivalent to repoint at, because the thing it measured (a generic model proposing a free-text diagnosis, checked against a global confidence score) no longer exists. The Fulfillment Playbook's determinism is proven instead by ordinary `pnpm test` — `fulfillment-capabilities.test.ts`'s Public Reference Scenarios (already so named before this cutover), `finding-policy.test.ts`, `fulfillment-playbook.test.ts` — ADR-0031's own framing (the Playbook, not the model, chooses every capability) makes a separate scripted-model eval run redundant for that part of the system. `src/insights/` (`compute-insights.ts`, `pnpm insights`, `pnpm onboarding:snapshot`, `web/src/lib/eval-snapshot.json`, the onboarding Drawer's chart) is removed for the same reason one level up: it aggregated free-text `diagnosis.hypothesis` strings and the retired `resolved`/`needs_more_data`/`needs_human` `Status` values across those same 15 tickets — a shape that has no analogue against a 2-value canonical Finding Code taxonomy over one Symptom Code. `pnpm evals:intake`/`pnpm evals:intake:live` (the Language Assistance intake-extraction accuracy suite) are untouched: they already measured the one model call that survives this cutover, on its own fixture set, independent of golden tickets.

**Deliberately deferred to a follow-up.** This cutover does not deploy the resource-oriented Investigation to AWS. `pnpm dev serve` runs the full `POST/GET /investigations` flow locally today; the *deployed* stack has no first-party investigation route at all until a follow-up migrates it to a DynamoDB-backed Lambda behind the existing API Gateway and demo-key authorizer. Standing up an interim, ephemeral, in-memory-repository Lambda as a stopgap was considered and rejected — it would duplicate work the follow-up already owns and give a false impression of durability the demo doesn't have. `README.md` and `docs/demo-script.md` say this plainly rather than leaving a reader to discover it by trying a dead URL.

## Consequences

The active suite now reads as six kinds of tests rather than one generic-contract suite plus a separate eval harness — Public Reference Scenarios (`src/capabilities/fulfillment-capabilities.test.ts`, already so named before this ticket), Finding Policy cases (`src/domain/finding-policy.test.ts`, `finding-source-pack.test.ts`), Fulfillment Playbook scenarios (`src/domain/fulfillment-playbook.test.ts`), Language Assistance evaluations (`src/language-assistance/*.test.ts`, `src/evals/intake-extraction-metrics.test.ts`, `src/api/intake-injection-sabotage-battery.test.ts`, `src/domain/explanation-improvement.test.ts`), adapter contracts (`src/gateway/*.contract.test.ts` and their fixture/live implementations, `src/mcp/server.test.ts`, `src/mcp/lambda-handler.test.ts`, `src/mcp/tools/search-support-knowledge.test.ts`), and a small end-to-end demo set (`src/api/investigations-app.test.ts`, `docs/demo-script.test.ts`). This is a description of what the suite already is post-cutover, not a physical directory reorganization — every other domain/gateway/kb test not named above (order context, the investigation repository, Knowledge Index build/search/embeddings) continues to exercise its own module directly and doesn't need to be forced into one of the six names to be legitimate coverage.

The eval/insights removal is a real capability loss for one narrow purpose: there is no longer a committed, aggregate view of outcome-category distribution across a fixed ticket set for onboarding material to cite. Nothing in this cutover's acceptance criteria asks for that view to be replaced, and the categories it aggregated (`resolved`/`needs_more_data`/`needs_human`, free-text diagnosis hypotheses) don't exist in the new contract to aggregate. If a future change wants an analogous view over the focused product, it starts from Investigation Decision/Decision Reason distribution across real or reference investigations, not a repointed `compute-insights.ts`.

Two Bedrock-calling code paths (`src/model/create-model.ts` and `src/language-assistance/bedrock-language-assistance.ts`) are now one: only AI SDK Core remains, and `MODEL_PROVIDER=glm`'s free-iteration path (ADR-0003/0018) is gone with it — a real, if narrow, loss of the free-local-iteration option those ADRs argued for. Re-adding a non-Bedrock provider now means wiring it into AI SDK Core's own provider interface, not reviving `create-model.ts`.
