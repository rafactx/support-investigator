# The live demo runs on one Cloudflare Worker with Workers AI; AWS CDK stays the reference deployment

The reference AWS deployment (ADR-0002) is meant to be up only during a demo window, and every route sits behind a shared key. A public demo has to stay up, cost nothing at rest, and let anyone run the deterministic flow (ADR-0047). We decided to host it on Cloudflare:

- **One Worker, one origin.** `src/cloudflare/worker.ts` serves the Investigations API at `/investigations`, the Support MCP at `/mcp` (stateless Streamable HTTP, a fresh server per request, as on Lambda, ADR-0007) and the SPA from Workers Static Assets (`web/dist`). `run_worker_first` sends only the API paths to the Worker; every other path is an asset or the SPA's `index.html` (hash routing, ADR-0041). Same origin means no CORS configuration at all. The MCP app is mounted by exact path, because its JSON pre-parse middleware would reject investigation routes if it were mounted at `/`.
- **D1 is the operational store here.** `D1InvestigationRepository` passes the same contract suite as the in-memory and DynamoDB adapters (ADR-0034/0035), run inside workerd against a local D1 by the Workers Vitest plugin. Each command is one `db.batch()`, which D1 runs as one transaction. Optimistic concurrency is enforced in SQL: the new event's revision is computed inside the `INSERT` from the projection, and only when it still equals the expected revision. Otherwise it is `NULL`, the `NOT NULL` constraint aborts the batch, and the adapter re-reads committed state to report a replay, a key conflict or a stale revision.
- **Workers AI is the default model.** `LANGUAGE_MODEL_PROVIDER=workers-ai` uses `@cf/meta/llama-3.3-70b-instruct-fp8-fast`: instruction-tuned, not a reasoning model (a reasoning model would spend the 300/700 output-token ceilings on thinking), and listed by Cloudflare as supporting JSON Mode, which structured output relies on. The AI SDK provider is `createAI` from `agents/models/ai-sdk`; `workers-ai-provider` is deprecated. Prompts, schemas, token ceilings and the timeout default stay in `createModelLanguageAssistance`, so Bedrock and Workers AI cannot drift. The timeout stays 4 s and is configurable up to 20 s (`LANGUAGE_ASSISTANCE_TIMEOUT_MS`) in case cold starts need more; a timeout only degrades to the deterministic path. Every call goes through AI Gateway, so each request sets `collectLog: false` and `skipCache: true`: ticket text must not be stored (ADR-0043).
- **Embeddings stay pinned to the index (ADR-0009).** `EMBED_PROVIDER=workers-ai` (`@cf/baai/bge-m3`: multilingual, 1,024 dimensions, the cheapest Workers AI embedding) lets `kb:refresh` rebuild the index over the REST API. Until someone does, the committed index stays `lexical` and needs no model at query time. The Worker imports the index as a JSON module, because Workers have no filesystem, and refuses to start with an index it cannot query (Bedrock Titan, local transformer).
- **Rate limits use two stores.** Per-client burst limits (create 10, model 3, writes 30, MCP 60 per minute) use the Workers Rate Limiting binding. It is free and needs no storage writes, but it only supports 10 s or 60 s periods and it counts per Cloudflare location, eventually consistently. So the hard bound on spend, the global daily model budget (default 50 calls per UTC day), is a D1 fixed-window counter: one upsert counts and decides, and D1 serializes writes. At the default model's prices one call costs well under 200 Neurons, so 50 calls fit the 10,000-Neuron daily free allocation. On the Workers Free plan, Workers AI fails rather than bills past that allocation, and the failure degrades to the deterministic path. This replaces ADR-0047's hourly per-client windows with per-minute ones on this platform; the rule names and the guard are unchanged.

The Worker bundle must not contain the AWS SDK, `@xenova/transformers` or `sharp`. The Support MCP module therefore no longer imports the Node HTTP server or the `EMBED_PROVIDER` switch: callers inject the query embedder, and the Worker has its own Language Assistance factory that cannot select Bedrock. `nodejs_compat` is on because the API uses `node:crypto` and `Buffer`.

The AWS CDK stack stays as the *reference AWS deployment*, unchanged, and still runs `cdk synth` in CI.
